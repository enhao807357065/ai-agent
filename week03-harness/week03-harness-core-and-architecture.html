WEEK03-HARNESS · PI 0.85.1

核心组件图与受治理 Agent 架构

核心原则：模型只提议动作；Pi Loop 只编排；所有副作用必须经由 ToolRuntime.execute()。Plan、Evidence、验证新鲜度、审批与 Checkpoint 共同决定任务是否真的完成。

01 · 核心组件图：职责与可信边界

模型与 Loop

  • 模型只产生 Tool Call / Final。
  • Pi 维护多轮协议消息与工具回合。
  • 自然语言 Final 是完成候选，不是完成事实。

执行与取消

  • Adapter 不读写文件，只转发到 Runtime。
  • 路径、参数、AbortSignal 在 Runtime 边界执行。
  • 测试取消后等待 child process close。

状态与证据

  • PlanStore 服务端盖章 step / call ID / version。
  • 测试绑定实际 workspace digest。
  • 同 scope 取最新结果，失败覆盖旧 pass。

02 · 架构图：一次受治理任务从提议到完成/暂停

审批与恢复

  • waiting_for_approval 禁止普通 resume。
  • 批准执行冻结调用，不让模型重生成 patch。
  • 恢复先比对 workspace 与 action 账本。

完成裁决

  • Step completed 是历史状态，不等于当前有效。
  • Completion Contract 重新检查验证新鲜度。
  • 失败或过期会反馈具体缺项到下一轮。

唯一副作用边界

  • Loop、Adapter、Approval 都不直接操作文件。
  • 所有 handler 都经 Runtime 校验与受控结果。
  • Sandbox/OS 隔离仍是未来可叠加层。
